- (constraint) PRD is final: Windows personal app, app-name-level tracking only, local-only v1, no interruptions or supervision, no content-level data collection.
- (version) .NET 10 and WPF were verified against Microsoft official documentation; Microsoft.Data.Sqlite stable 10.0.11 was verified on NuGet on 2026-08-26.
- (decision) AD-1: Use a layered, single-process WPF desktop application with a long-lived background host; UI, sampling, and reporting share one process and communicate only through application services, preventing a separate recorder and UI from owning competing data lifecycles.
- (decision) AD-2: Use Win32 foreground-window and session-scoped last-input APIs through a thin interop adapter; it may return only stable application identity and idle duration, never window title, path, content, keyboard data, or mouse trajectory.
- (decision) AD-3: Persist append-only raw focus segments and user rules in one local SQLite database; reports are query-derived and are never an independent source of truth, preventing stale statistics after recategorization.
- (decision) AD-4: One recording coordinator exclusively owns state transitions and writes; UI actions are commands handled by application services, preventing concurrent segment writes and inconsistent pause/idle/day-boundary handling.
- (decision) AD-5: Stable application identity uses display name plus executable filename or package ID; process ID and executable path are transient/interoperability-only and are never persisted.
- (decision) AD-6: Local database and exports stay inside the per-user LocalApplicationData directory; export is aggregate-only through a dedicated exporter, and v1 has no outbound network client.
- (decision) AD-7: Sampling and aggregation use local wall-clock instants stored as UTC and report in the current local timezone; each segment is split at lock, sleep, resume, active-app change, idle transition, and local midnight.
- (decision) AD-8: Use a best-effort startup registration adapter with a user-visible toggle; failure is shown only in the app/tray status and never produces an interruptive notification.
- (decision) AD-16: ApplicationIdentityId is nullable on FocusSegment and required only for focus segments; idle and all non-focus dispositions never carry identity. Exclusion is forward-only at signal handling: while the rule is active, coordinator writes excluded segments without identity; removing it affects only future signals.
- (decision) AD-17: When a segment is created or split, persist its local_date and UTC offset using the then-current local timezone. Reports, export, and single-day deletion group by stored local_date, so historical dates do not change if the computer timezone later changes.
- (event) Reviewer gate completed: lint passed with zero findings; PRD reconciliation, technology verification, adversarial review, and final re-review found no remaining critical or high issue after AD-9 through AD-17.
- (event) spine finalized
- (decision) AD-18: Report queries require a local-date parameter and return application rows, category rows, and an unclassified application list for that date; the UI only renders these query models and does not recompute aggregates.
- (decision) AD-19: All local structured logs are SQLite rows in the same database. Any future sync must be opt-in after showing that only aggregate summaries are uploaded; raw segments and forbidden data remain ineligible.
- (change) Final polish added AD-18 report query model and AD-19 same-database logging plus future explicit sync authorization; these close remaining medium reviewer findings.
