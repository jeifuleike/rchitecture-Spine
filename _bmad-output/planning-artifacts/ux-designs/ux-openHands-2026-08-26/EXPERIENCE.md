# 专注记录器 - Experience Spine

## Foundation

单一 Windows 桌面表面，WPF 外壳 + 系统托盘。`DESIGN.md` 是视觉身份参考；本文定义信息架构、行为、状态和交互。体验继承 Windows 原生桌面习惯：窗口、菜单、按钮、复选框、滑块、日期选择器、确认对话框均优先使用熟悉控件。

产品姿态：后台自动记录，前台只在 Stove 主动打开时展示复盘和控制。正常记录期间不弹窗、不提醒、不追问活动内容。

## Information Architecture

| Surface | Reached from | Purpose |
| --- | --- | --- |
| 今日报表 | 主窗口默认页 / 托盘“打开报表” | 查看所选日期的专注总时长、空闲时长、分类排行、应用排行和未分类应用 |
| 历史日期选择 | 今日报表左栏 | 切换本地自然日，读取该日统计 |
| 应用分类 | 未分类列表 / 应用行操作 | 给稳定应用身份设置或修改分类，历史统计视图随当前规则重算 |
| 设置 | 主窗口侧栏 / 托盘菜单 | 空闲阈值、开机自启动、暂停/恢复、排除应用 |
| 数据控制 | 设置页 | 删除某日数据、删除全部数据、导出 CSV 或 JSON 摘要 |
| 托盘菜单 | 系统托盘图标右键 | 打开报表、暂停/恢复、状态查看、退出 |

主窗口关闭只隐藏窗口，不停止记录。显式“退出”才结束后台宿主。

## Voice and Tone

微文案必须中性、短、可解释。品牌姿态见 `DESIGN.md`。

| Do | Don't |
| --- | --- |
| “今天记录了 5 小时 20 分钟专注时间。” | “你今天高效工作了 5 小时！” |
| “空闲时间未计入专注。” | “你离开太久了。” |
| “未分类应用 3 个。” | “还有 3 个问题应用。” |
| “删除 2026-08-26 的本地记录？” | “清空你的历史？” |
| “导出统计摘要。” | “上传数据” |

错误文案只说明事实和下一步，例如“当前无法读取前台应用，记录会继续重试。详情在本地日志中。”不得要求用户解释刚才在做什么。

## Component Patterns

| Component | Use | Behavioral rules |
| --- | --- | --- |
| 日期选择器 | 报表左栏 | 默认选中今天；切换日期只触发查询，不改写数据 |
| 总览数字 | 报表顶部 | 显示专注总时长和空闲时长；空闲必须独立，不进入专注总时长 |
| 分类排行行 | 报表 | 累计时长降序，名称升序打破并列；占比条分母只包含 focus 片段 |
| 应用排行行 | 报表 | 显示应用名、分类、累计专注时长；行操作可修改分类或排除应用 |
| 未分类列表 | 报表 | 只列未分类 focus 应用；每行提供分类下拉和保存动作 |
| 分类下拉 | 应用分类 | 默认类别：编程、AI 对话、资料阅读、写作、沟通、娱乐/休闲、其他、未分类；用户类别遵循设置中的生命周期 |
| 暂停/恢复控件 | 托盘和设置 | 暂停后不生成新采样；恢复从当前活跃应用开始新片段 |
| 排除应用列表 | 设置 | 添加或移除稳定应用身份；规则只影响未来信号，不恢复历史排除时段 |
| 空闲阈值控件 | 设置 | 1-60 分钟，默认 5 分钟；修改从下一信号生效 |
| 导出按钮 | 数据控制 | 导出 CSV 或 JSON 摘要；不导出原始片段 |
| 删除确认 | 数据控制 | 单日删除和全部删除分开；确认文案必须点明范围 |

## State Patterns

| State | Surface | Treatment |
| --- | --- | --- |
| 首次启动无数据 | 今日报表 | 显示空报表和被动状态：“还没有可显示的记录。”不提示打卡 |
| 正在记录 | 托盘 / 设置 | 状态可见但不弹通知；托盘菜单显示“正在记录” |
| 已暂停 | 托盘 / 设置 / 报表顶部 | 清楚显示暂停状态；主操作变为“恢复记录” |
| 空闲中 | 报表 | 空闲片段累计到空闲时长；不显示为专注应用 |
| 锁屏或睡眠后恢复 | 报表 | 锁屏/睡眠不计入专注；恢复输入后开始新片段 |
| 未分类过多 | 报表 | 只显示未分类列表和分类控件；不使用警告弹窗 |
| 采集适配器失败 | 设置 / 托盘状态 | 被动显示错误码和简短说明；继续重试，不打断 |
| 导出完成 | 数据控制 | 原地显示完成状态和文件路径；不主动打开网络或上传 |
| 删除完成 | 数据控制 | 原地刷新当前日期报表；全部删除后回到无数据状态 |

## Interaction Primitives

- 托盘左键打开/聚焦主窗口，右键打开菜单。
- `Esc` 关闭浮层或对话框；主窗口中的 `Esc` 不退出记录。
- 日期切换、分类修改、排除应用、删除和导出都是用户主动动作。
- 修改分类后，报表立即按当前规则重新查询；原始片段不改写。
- 关闭窗口隐藏到托盘；显式退出需要菜单项或设置页按钮。
- 破坏性动作必须有确认对话框；确认按钮文案包含范围，例如“删除这一天”。
- 禁止：生产力评分、每日推送、目标提醒、网站拦截、强制复盘、询问“刚才在做什么”。

## Accessibility Floor

- 所有交互控件可键盘访问，Tab 顺序与视觉阅读顺序一致。
- 列表行、下拉、按钮和托盘菜单项有清晰名称、角色和状态。
- 色彩不是唯一信息来源；专注、空闲、未分类必须同时有文本标签。
- 主要点击目标不小于 32px，托盘菜单遵循系统默认尺寸。
- 报表数字和时长文本支持 Windows 文本缩放；文本不得被截断到不可理解。
- 删除确认必须支持屏幕阅读器朗读删除范围和不可逆含义。

## Privacy Interaction Boundaries

- UI 不展示窗口标题、文件路径、网页标题、聊天对象、截图、键盘输入或鼠标轨迹。
- 应用身份展示只使用应用显示名和可执行文件名或包标识的安全摘要。
- 导出界面只提供统计摘要导出，字段为日期、分类、应用名、累计专注时长和空闲时长汇总。
- v1 不出现登录、账号、同步或远程上传入口。未来同步必须作为独立 opt-in 流程重新设计。

## Responsive & Platform

| Window size | Behavior |
| --- | --- |
| 宽屏 1100px+ | 左侧日期/设置导航，右侧报表；分类排行和应用排行可并排 |
| 标准 900-1099px | 左侧导航保留，报表垂直堆叠 |
| 窄窗口 < 900px | 导航折叠为顶部行，所有报表列表单列显示 |

平台仅承诺 Windows 11 22H2+ 和架构指定的受支持 Windows 10 LTSC/Enterprise。不要为 v1 设计移动端或 Web 响应式体验。

## Inspiration & Anti-patterns

- **借鉴系统监视器类工具：** 清晰状态、低装饰、用户主动打开才看。
- **借鉴 ActivityWatch/ManicTime 的本地记录模型：** 自动采样和空闲处理，但 v1 更严格地限制到应用名粒度。
- **拒绝效率教练模式：** 不评分、不提醒、不催促。
- **拒绝内容级分析：** 不读取网页标题、文档名或聊天内容，即使这样会降低分类自动化。
- **拒绝复杂数据可视化：** v1 用列表和基础占比满足复盘，不以图表丰富度作为价值。

## Key Flows

### Flow 1 - 晚上复盘今天的专注分布（Stove，晚上 10:40）

1. Stove 从托盘打开专注记录器。
2. 今日报表默认显示今天的专注总时长和空闲时长。
3. Stove 先看分类排行，确认今天大部分时间是否落在编程、AI 对话或写作。
4. 他滚到应用排行，看到每个分类来自哪些应用。
5. 他发现一个常用 AI 客户端仍在“未分类”。
6. 他在未分类列表里选择“AI 对话”并保存。
7. **Climax:** 报表原地刷新，分类排行和未分类列表同步变化；Stove 能解释今天的主要时间去向，而没有被评价。

失败路径：分类保存失败时，行内显示“没有保存，稍后可重试。”不弹窗追问。

### Flow 2 - 忘记工具存在但仍持续记录（Stove，工作日早上）

1. Stove 登录 Windows 后直接开始工作，没有打开主窗口。
2. 专注记录器随系统启动，在托盘中保持被动状态。
3. Stove 切换 IDE、浏览器、AI 客户端和文档工具；采样器只记录稳定应用身份。
4. 午饭时电脑超过空闲阈值，后续时间进入空闲状态。
5. 下午恢复输入后，记录器从当前活跃应用开始新片段。
6. Stove 晚上打开报表。
7. **Climax:** 报表能解释全天应用和分类分布，午饭离开电脑的时间没有污染专注总时长。

失败路径：如果开机自启动失败，状态只在托盘/设置中被动显示；不会在开机时弹窗打断。

### Flow 3 - 控制本地数据（Stove，周末整理数据）

1. Stove 打开设置里的数据控制。
2. 他选择导出本周某天的统计摘要为 CSV。
3. 导出完成后，界面显示本地文件路径。
4. 他再选择删除某一天的记录。
5. 删除确认对话框明确写出日期和“只删除本地记录”。
6. 他确认删除。
7. **Climax:** 当前日期报表变为空状态，分类规则仍保留；Stove 明确知道被删的是哪一天，不是全部配置。

失败路径：全部删除是单独动作，不能通过单日删除误触发。
