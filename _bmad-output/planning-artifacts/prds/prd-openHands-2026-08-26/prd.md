# PRD: 专注记录器

## 0. 文档目的

本文档定义一个 Windows 个人自用桌面端小工具的 MVP：它在后台自动记录用户每天真正把电脑时间花在哪些应用上，并按日生成本地统计。本文档面向后续 UX、架构和实现拆分使用；功能需求使用 FR 编号，用户旅程使用 UJ 编号，v1 默认决策和非阻塞后续问题在末尾集中索引。

## 1. 愿景

专注记录器是一个安静运行在 Windows 后台的个人时间统计工具。它不监督、不提醒、不打断，只在用户事后想复盘时，提供“今天主要专注在哪些应用和类别上”的记录。

这个产品的核心判断是：对个人自用来说，粗粒度但稳定、无打扰的记录比细粒度但侵入的分析更重要。v1 只需要识别应用名并归类，不追踪浏览器网页、文档内容、聊天对象、键盘输入、截图或屏幕内容。

长期方向可以支持后端同步，但隐私边界必须先定清楚：本地保留详细记录；未来即使上传，也只上传聚合后的统计数据，不上传具体分析明细或原始活动记录。

## 2. 目标用户

### 2.1 待完成任务

- 当一天结束时，Stove 想知道自己电脑时间主要花在了哪些应用和类别上，而不是凭感觉回忆。
- 当某段时间很忙却说不清忙什么时，Stove 想查看应用级时间分布，判断是否真的专注在关键工作上。
- 当使用统计工具时，Stove 不想被提醒、评分、监督或打断。
- 当数据涉及个人电脑活动时，Stove 想默认只保存在本地，并控制未来是否同步统计摘要。

### 2.2 非目标用户（v1）

- 团队管理者、雇主、家长控制场景。
- 需要网页级、文件级、聊天对象级或屏幕内容分析的用户。
- 需要跨设备同步、移动端统计或公开发布版本的用户。

### 2.3 关键用户旅程

- **UJ-1. Stove 晚上复盘今天的电脑专注分布。** Stove 白天正常使用电脑，专注记录器在后台自动记录活跃应用。晚上他打开报表，看见今天各应用和类别的总时长、主要专注对象和未分类项；如果某个应用分类不合适，他可以调整分类规则，后续统计自动使用新分类。

- **UJ-2. Stove 忘记工具存在，但数据仍然持续记录。** Stove 开机后直接开始工作，没有手动启动记录，也没有收到任何提醒。专注记录器随系统后台启动，自动采样活跃应用；当电脑长时间无输入时，系统不把离开电脑的时间计入专注时长。

## 3. 术语表

- **专注记录器** — 本产品，Windows 后台运行的个人应用级活动统计工具。
- **活跃应用** — 当前用户正在操作或位于前台的 Windows 应用。
- **活动采样** — 专注记录器按固定频率读取活跃应用，并保存时间片段的行为。
- **专注片段** — 连续一段时间内活跃应用保持一致或被归入同一类别的记录。
- **分类** — 将应用名映射为日常活动类别，例如编程、AI 对话、资料阅读、写作、沟通、娱乐/休闲、其他、未分类。用户可以自定义更个人化的分类名。
- **本地数据** — 保存在当前电脑上的原始活动记录、分类规则和统计结果。
- **统计摘要** — 按天、应用和分类汇总后的聚合数据；未来后端同步只允许上传该类数据。
- **排除应用** — 用户明确指定不进入统计的应用。
- **暂停记录** — 用户主动临时停止活动采样的状态。
- **稳定应用身份** — 用于识别同一应用的非内容级字段组合，至少包含应用显示名和可执行文件名或 Windows 包标识；不得包含文件路径、窗口标题或内容。

## 4. 功能

### 4.1 后台自动记录

**描述：** 专注记录器在 Windows 后台自动运行，定期识别活跃应用并生成专注片段。它不弹窗、不询问、不评分，只做记录。实现 UJ-1、UJ-2。

#### FR-1: 后台运行

专注记录器可以在 Windows 后台运行，并支持随系统启动自动开始记录。

**可测试结果：**
- 用户登录 Windows 后，专注记录器可以在不打开主界面的情况下开始记录。
- 用户可以在设置中开启或关闭开机自启动。
- 主界面关闭后，记录进程仍可继续运行，除非用户明确退出或暂停记录。

#### FR-2: 活跃应用采样

专注记录器必须按应用名粒度记录活跃应用，不要求记录网页标题、文档名、文件路径、聊天对象或屏幕内容。

**可测试结果：**
- 当用户从一个应用切换到另一个应用时，后续采样记录新的活跃应用。
- 每条原始记录至少包含时间戳、应用名和稳定应用身份。
- 默认采样间隔为 5 秒。
- 少于 15 秒的短暂应用切换默认合并回前后相同的专注片段。
- v1 不保存截图、键盘输入、鼠标轨迹或窗口内容。

#### FR-3: 空闲时间处理

专注记录器应识别电脑空闲状态，并避免把明显离开电脑的时间计入专注片段。默认空闲阈值为 5 分钟。

**可测试结果：**
- 当用户超过空闲阈值没有键盘或鼠标输入时，后续时间进入“空闲/未计入专注”状态。
- 用户重新输入后，系统从当前活跃应用开始新的专注片段。
- 空闲阈值可以在本地设置中调整。
- Windows 锁屏、睡眠和唤醒应切断当前专注片段，并在恢复输入后开始新片段；锁屏和睡眠不计入专注时长。
- 跨自然日持续的专注片段必须按本机时区拆分到对应日期。

#### FR-4: 完全无打扰

专注记录器不得主动弹出专注提醒、监督提示、确认问题、每日评价或打断式通知。

**可测试结果：**
- 正常记录过程中不会出现“你刚才在做什么？”一类确认弹窗。
- 正常记录过程中不会出现效率评分、分心提醒或目标催促。
- 错误或权限问题可以通过主界面或系统托盘状态展示，但不得频繁打断用户。

### 4.2 分类与统计

**描述：** 专注记录器将应用级记录归入日常类别，生成可复盘的每日统计。分类服务于事后理解，不服务于监督。实现 UJ-1。

#### FR-5: 应用分类

专注记录器必须支持把应用名映射到分类：编程、AI 对话、资料阅读、写作、沟通、娱乐/休闲、其他、未分类。

**可测试结果：**
- 未配置规则的应用默认进入“未分类”。
- 用户可以为某个应用设置或修改分类。
- 修改分类后，系统可以重新计算历史统计；分类修改影响历史统计视图，但不改写原始记录。

#### FR-6: 每日统计

专注记录器必须按自然日展示应用和分类维度的统计摘要。

**可测试结果：**
- 用户可以查看某天各应用的累计时长。
- 用户可以查看某天各分类的累计时长。
- 用户可以看到当天排名靠前的专注应用和专注分类。
- 空闲时间应单独展示，且排除在专注总时长外，避免总时长误解。
- 统计日期按本机时区的自然日计算。
- 排名靠前的应用和分类按累计专注时长降序排列；并列时按名称排序，保证结果稳定。
- 时长展示精确到分钟；少于 1 分钟的片段可以合入总时长但显示为“<1 分钟”。
- 分类占比的分母不包含空闲时间和排除应用时间。
- 未分类应用必须同时计入专注总时长和“未分类”分类，直到用户配置分类规则。

#### FR-7: 轻量报表界面

专注记录器应提供一个只在用户主动打开时出现的本地报表界面。

**可测试结果：**
- 用户主动打开主界面后，可以查看今天和历史日期的统计摘要。
- 报表界面不显示监督性文案，例如“你浪费了 X 小时”。
- 报表至少包含按应用统计、按分类统计和未分类应用列表；v1 不要求复杂图表，列表和基础占比即可。

### 4.3 本地数据与未来同步边界

**描述：** v1 默认所有数据只保存在本机。未来可以引入后端，但只能同步聚合统计摘要，不能上传具体分析数据。实现 UJ-1、UJ-2。

#### FR-8: 本地优先存储

专注记录器必须在 v1 中把本地数据保存在当前 Windows 设备上，不依赖后端即可完整使用。

**可测试结果：**
- 离线状态下，记录、分类和报表功能仍可使用。
- 卸载或清除数据前，系统不得把本地数据上传到远程服务。
- 用户可以删除本地数据。
- 本地数据默认永久保留，直到用户手动删除；v1 不做自动清理。

#### FR-9: 未来同步隐私边界

如果后续加入后端同步，同步范围必须限制为统计摘要，并且必须由用户显式开启。

**可测试结果：**
- 默认状态不上传任何数据。
- 同步开启前，界面必须说明上传的是聚合统计摘要，而不是具体应用活动明细。
- 同步数据不得包含原始专注片段、窗口标题、截图、键盘输入、文件路径或聊天内容。

### 4.4 用户控制

**描述：** 专注记录器默认自动运行，但必须给用户基本控制权，避免“静默记录”变成不可控监控。控制入口只能在用户主动打开界面时出现，不主动打扰。实现 UJ-1、UJ-2。

#### FR-10: 暂停与恢复记录

用户可以主动暂停记录，并在需要时恢复记录。

**可测试结果：**
- 暂停记录后，专注记录器不再生成新的活动采样。
- 恢复记录后，专注记录器从当前活跃应用开始新的专注片段。
- 暂停状态应在主界面或托盘状态中可见。

#### FR-11: 排除应用

用户可以把指定应用加入排除应用列表，使其不进入专注统计。

**可测试结果：**
- 被排除应用成为活跃应用时，该时间不计入应用统计或分类统计。
- 用户可以添加、移除和查看排除应用。
- 排除应用规则只保存在本地。

#### FR-12: 删除与导出本地数据

用户可以删除本地数据，并导出本地统计摘要用于个人备份和检查。v1 支持 CSV 或 JSON 导出统计摘要，不导出原始活动记录。

**可测试结果：**
- 用户可以删除某一天的数据。
- 用户可以删除全部本地数据。
- 用户可以导出本地统计摘要。
- 导出的统计摘要至少包含日期、分类、应用名、累计专注时长和空闲时长汇总，字段保持最小化。
- 导出行为由用户主动触发，不自动上传。

## 5. 跨功能约束与非功能需求

- **隐私：** v1 不上传数据；不采集截图、键盘输入、鼠标轨迹、窗口内容、网页标题、文件路径或聊天对象。
- **性能：** 后台记录平均 CPU 占用应低于 1%，内存占用应低于 150 MB。
- **可靠性：** 正常运行一天后，应用级统计不应丢失超过 1 分钟的连续前台应用活动；采样进程异常退出后应能在下次启动时继续记录。
- **数据可解释性：** 报表必须能解释“某个分类为什么有这些时间”，至少能追溯到应用名级别。
- **无打扰：** 产品不得把记录功能变成监督、提醒、打卡或强制复盘机制。

## 6. 非目标

- v1 不做网页标题、URL、浏览器标签页、IDE 文件、文档标题、聊天对象或屏幕内容级分析。
- v1 不做生产力评分、目标监督、分心提醒、强制确认或每日推送。
- v1 不做团队管理、雇员监控、家长控制或第三方汇报。
- v1 不做移动端、跨设备同步或云端账号系统。
- v1 不上传本地活动明细。

## 7. MVP 范围

### 7.1 范围内

- Windows 桌面端后台记录。
- 活跃应用名采样。
- 空闲时间识别：默认空闲阈值 5 分钟，可配置；锁屏和睡眠不计入专注时长。
- 应用到分类的本地映射。
- 每日应用统计和分类统计。
- 未分类应用列表。
- 暂停/恢复记录。
- 排除应用列表。
- 删除某天或全部本地数据。
- 导出本地统计摘要：支持 CSV 或 JSON，不导出原始活动记录。
- 本地数据存储、清除和离线使用。
- 完全无打扰运行。

### 7.2 MVP 范围外

- 后端同步：推迟到 v2，且只允许统计摘要。
- 内容级分析：超出用户确认的应用名粒度。
- AI 自动总结：可能带来隐私和解释性复杂度，v1 不需要。
- 复杂图表和目标管理：容易把工具推向监督者，不符合当前产品原则。
- 自动数据清理：v1 默认永久保留本地数据，用户手动删除。

## 8. 成功指标

**主要**

- **SM-1:** 连续 7 天在无手动干预的情况下产生可查看的每日统计。验证 FR-1、FR-2、FR-4、FR-6。
- **SM-2:** 用户每周至少主动查看 1 次报表，并认为统计能帮助回忆当天主要专注方向。验证 FR-6、FR-7。

**次要**

- **SM-3:** 未分类应用占总专注时长比例在用户配置一周后低于 20%。验证 FR-5。
- **SM-4:** 后台记录不让用户感觉到卡顿或被打扰。验证 FR-3、FR-4 和跨功能性能约束。
- **SM-5:** 用户能在 1 分钟内完成暂停记录、排除应用、删除数据或导出摘要中的任一操作。验证 FR-10、FR-11、FR-12。

**反指标（不要优化）**

- **SM-C1:** 不以“减少娱乐时长”作为成功指标；本产品记录事实，不替用户判断价值。
- **SM-C2:** 不以提醒次数、确认次数或打开频率作为成功指标；它应该能被忘记，但仍可靠记录。

## 9. 非阻塞后续问题

这些问题不阻塞 v1 进入架构与故事拆分；按下列触发条件回看。

1. 产品名称 — 负责人：Stove。回看条件：进入 UI 文案、安装包命名或公开分享前。v1 默认使用“专注记录器”。
2. 长时间无输入但仍在专注的场景 — 负责人：Stove。回看条件：首周使用发现视频观看、会议等场景被误判为空闲时。v1 默认仍按空闲阈值处理。
3. 时间线视图 — 负责人：Stove。回看条件：列表和基础占比无法解释一天的上下文时。v1 不内置时间线视图。
4. “AI 对话”分类识别 — 负责人：Stove。回看条件：浏览器或多客户端 AI 使用导致分类不稳定时。v1 默认由用户按应用或稳定应用身份手动映射。
5. 后端统计摘要字段 — 负责人：Stove。回看条件：开始 v2 同步设计前。v1 不预留云端字段，只保持本地统计摘要可导出。

- FR-2 — v1 合并少于 15 秒的短暂切换以减少统计噪声。
- FR-3 — 默认空闲阈值为 5 分钟。
- FR-3 — 空闲阈值需要可配置。
